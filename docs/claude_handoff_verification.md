## 2. Contradictions or missing files

- **Entry point and filename conventions differ.** The handoff describes `Julia/mps_calc.jl`, not v1's `Julia/0mps_calc.jl`. The former writes literal `_1024_` chi names ([lines 306–308](../Julia/mps_calc.jl#L306-L308)); the latter writes `_512_` cutoff or chi names ([lines 852–866](../Julia/0mps_calc.jl#L852-L866)). Neither convention may be generalized across both scripts.
- **Split-2 label discrepancy.** The handoff generalizes split 2 as `seq`, but `Julia/mps_calc.jl` uses `sp` for every non-1 split ([line 306](../Julia/mps_calc.jl#L306)). `seq` is supported by the other script and Python mapping; do not classify this difference as a bug or intended behavior without owner direction.
- **TKE implementation differs from the narrative.** The checked-in jet and JHS spectrum scripts sum whole-array component variances ([py/velocity_spectrum_stats.py:360–361](../py/velocity_spectrum_stats.py#L360-L361), [py/jhs_velocity_spectrum_stats.py:324–325](../py/jhs_velocity_spectrum_stats.py#L324-L325)). They do not implement the claimed plane-wise TKE profile. No alternative authoritative implementation was selected.
- **Output-directory inference is unsupported.** Generated component jobs explicitly `cd` to `rundir` ([py/gen_mps_chi_jobs.py:65](../py/gen_mps_chi_jobs.py#L65)); the writer receives a relative filename ([Julia/mps_calc.jl:307](../Julia/mps_calc.jl#L307)). A log directory is not evidence that MAT outputs were written there. Actual external result locations remain unknown.
- **Temperature naming remains inconsistent in source.** The handoff says the `temp` mistake was corrected, but the filter cache generator still defaults to `mixfrac,temp,Y_O2,Y_OH,Y_CO2` ([py/make_filtered_cube.py:75–76](../py/make_filtered_cube.py#L75-L76)). The filtered-statistics consumer requests `T` ([py/run_filtered_stats.py:103–108](../py/run_filtered_stats.py#L103-L108)). This does not establish which external copy ran.
- **Missing from this checkout:** `chi262/` and its claimed seven-script suite, staged submitter and environment diagnostic; `map_velocity_fill.py`; `diagnose_velocity_dat.py`; `dat_to_mat.py`; `check_mat_format.py`; `submit_jet_vel_analysis.sh`; `submit_cutoff_sweep.sh`; and a standalone `collect_results.sh`. These names were checked against repository file listings. Absence here says nothing about external CRC copies. `py/gen_cutoff_jobs.py` contains collector generation ([lines 176–190](../py/gen_cutoff_jobs.py#L176-L190)); generated text is not evidence that a collector ran.
- **Q-R constant exists in a different file.** The original [py/7FI_MPS_3D_1024cubed_t1_joint_pdf_QR.py:21](../py/7FI_MPS_3D_1024cubed_t1_joint_pdf_QR.py#L21) contains `Qw_comp=9.171738021735438` and passes it to plotting ([line 173](../py/7FI_MPS_3D_1024cubed_t1_joint_pdf_QR.py#L173)). The absent chi262 variant, provenance of this constant, and claim that a result is wrongly normalized are not independently established.
- **Internal handoff references are unreliable.** Its velocity-data discussion points to section 8.1, which actually discusses the cutoff sweep; references to sections 8.4/8.5 and reviewer/rejection detail are not supplied by the corresponding sections. Those references are not supporting evidence.
